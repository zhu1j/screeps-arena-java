# 教程 10 关 Java 版 · 通关操作步骤

> 工程：`E:\Program Files (x86)\Game\ScreepsArenaDemo\ScreepsArena`
> 代码：`src\main\java\cn\net\zhu\tutorial\level01` ～ `level10`（每关一个包，一份带注释的可过关代码）

## 一、一次性准备

1. 环境（本机已验证可用；换机器时改 `build.cmd` 顶部两行即可）：
   - JDK：`D:\.jdks\jdk-25_windows-x64_bin\jdk-25`
   - Maven 本地仓库：`D:\maven\repository`（绑定库和 TeaVM 都在里面）
2. 打开工程目录，构建一次：

   ```powershell
   cd "E:\Program Files (x86)\Game\ScreepsArenaDemo\ScreepsArena"
   .\build.cmd
   ```

   看到 `BUILD SUCCESS` 就算成功（约十几秒）。构建会产出 11 个 `main.mjs`：

   - `dist\main.mjs`、工程根 `main.mjs` —— 竞技场 Demo bot，与教程无关；
   - `dist\tutorial\level01\main.mjs` ～ `dist\tutorial\level10\main.mjs` —— 教程 10 关，一关一份。

## 二、每关固定操作（首次每关做一次，之后游戏会记住）

1. 打开游戏里对应的教程关卡；
2. 在关卡页面把「代码目录」改绑到：

   ```
   E:\Program Files (x86)\Game\ScreepsArenaDemo\ScreepsArena\dist\tutorial\levelNN
   ```

   （`NN` = `01`…`10`，和关卡号一一对应，见下表）
3. 点 **PLAY**，看日志面板和画面；
4. 通过后进下一关，重复第 2 步绑它自己的目录。

> 为什么每关都要绑一次：游戏客户端给每个教程关**分别保存**各自的代码目录（一关一个路径）。
> 绑定是永久保存的，以后重玩这一关不用再绑。
> 每关的目录里只有一个 `main.mjs`；客户端会把整个目录打包上传（上限 10MB），只认根目录里的 `main.mjs`。

## 四、改了代码之后

1. 回到工程目录重新 `.\build.cmd`；
2. **重开一局**——代码是开局时载入的，对局中不会热更新。

### 只想重编第 7 关（不重编其它产物）

`pom.xml` 里每一关都是一段独立的 TeaVM `<execution>`（`id` 是 `tutorial-level-01` … `tutorial-level-10`），
可以直接点名只跑其中一段：

```powershell
cd "E:\Program Files (x86)\Game\ScreepsArenaDemo\ScreepsArena"
mvn -B -ntp compile org.teavm:teavm-maven-plugin:0.15.0:compile@tutorial-level-07
```

`07` 换成 `08` 就是只编第 8 关。中间空开写的 `compile` 不能省：它先把 Java 编译成 `target\classes`，
TeaVM 再照着 class 生成 `dist\tutorial\level07\main.mjs`；少了它，TeaVM 会拿上一次的旧 class 去编，
改了代码也不生效。

## 五、常见问题

- **在 `src\main\java\...\level07` 里敲 `.\build.cmd` 报"不是内部或外部命令"**：`build.cmd` 在工程根目录，
  而 Maven 只读**当前目录**的 `pom.xml`。先 `cd` 回工程根再跑，别在源码包里跑。
- **改了 Java 代码，游戏里没变化**：构建成功 ≠ 对局里生效。按顺序查三件事——
  ① 构建输出是 `BUILD SUCCESS`；② `dist\tutorial\level07\main.mjs` 的修改时间变新了；
  ③ 在游戏里**重开一局**。
- **第 7 关"一直孵化但不移动、出生点被堵死"**：这是"先孵化、后移动"的顺序问题，
  详见 `tutorial-docs\java\关卡07-Spawn-creeps.md` 的「真机上的两个坑」。
- **日志面板完全空白**：先查代码目录是否绑对（选中的就是 `dist\tutorial\level01` 这种含 `main.mjs` 的一层，
  不要多进也不要少进），再确认构建成功后**重开了一局**。
- **看到 `孵化失败：...`**：第 7、10 关出现是正常现象（能量没攒够/上一只还在孵化，代码会自动重试）。
- **第 10 关想调难度**：改 `level10\Main.java` 顶部常量（`EARLY_*`、`WANTED_*`、`MAX_FIGHTERS_UNDER_ATTACK`），
  重新构建、重开局即可。
- **想学/改每关逻辑**：每个 `Main.java` 顶部注释都写了本关目标、官方 JS 写法对照和用到的 Java API。
- **竞技场 bot 不受影响**：工程根的 `main.mjs` 仍然是 `cn.net.zhu.demo.Bot` 的（Spawn and Swamp 用的那个）。

## 六、原理速览（为什么能这样用）

游戏只认「代码目录根部的 `main.mjs`」，而 `pom.xml` 里为每一关配了一个 TeaVM 编译目标
（`tutorial-level-01` … `tutorial-level-10`），各自把对应包的 Java 代码编译成 `main.mjs`
写进 `dist\tutorial\levelNN\`。所以每关的目录天生就是一个可绑定的代码文件夹。
想加新关卡：复制一段 `<execution>`、改 `<mainClass>` 和 `<targetDirectory>`，再新建对应的包即可。
