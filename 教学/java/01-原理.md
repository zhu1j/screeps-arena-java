# 01 · 原理：Java 是怎么变成游戏能跑的代码的

## 一句话

对局里没有 JVM。Java 只在你的电脑上参与**构建**：
`Java 源码 → javac 字节码 → TeaVM 翻译成 JavaScript → main.mjs（ES module）`。
游戏客户端把 `main.mjs` 提交给服务器，服务器每 tick 调用其中的 `loop()`。

## 全链路

1. 你写 Java 策略（例如 `bot.harvest.Main`）。
2. `mvn package` 做两件事：javac 编译；TeaVM 把**用到的**类（含绑定库）翻译成 JS。
3. 产物 `dist/<关卡>/main.mjs`——纯 JS 的 ES module，里面没有任何 Java 运行时。
4. 游戏里把代码目录指向该文件夹，点 PLAY；客户端把目录下的文件提交给服务器。
5. 服务器加载 `main.mjs`，每个 tick 调用导出的 `loop()`。

## 绑定库做了什么

`screeps.arena` 包把游戏的 JS API 包成 Java 类：

- `Game`：全局函数——`getTicks`、`log`、`getObjectsByPrototype`、`findClosestByPath`、`createConstructionSite`……
- `GameObjects`：查找 + 常用快捷方法——`myCreeps()`、`enemyCreeps()`、`mySpawn()`、`sources()`……；
  并保证同一游戏对象在整场比赛里是同一个 Java 实例（按 id 缓存）。
- 包装类：`Creep`、`StructureSpawn`、`StructureTower`、`Flag`、`Source`……方法名尽量贴近官方 JS
  （`moveTo`、`attack`、`transfer`），返回值尽量用 Java 类型（`ErrorCode`、`int`、`List<T>`）。

### 几个适配决策（为什么要这样写）

- **入口**：官方要求模块导出 `loop` 函数；绑定库用 `@JSExport` 把 `public static void loop()` 导出成 JS 函数。
  这是 TeaVM 的机制，也是入口类必须写这个注解的原因。
- **跨 tick 状态**：官方 JS 用模块顶层变量；Java 里对应**类的静态字段**（`private static Creep creep1;`）。
  不要用实例字段——游戏每 tick 不会帮你保留对象。
- **常量**：JS 的 `ERR_NOT_IN_RANGE` 是数字、`RESOURCE_ENERGY` 是字符串；Java 用枚举
  `ErrorCode.ERR_NOT_IN_RANGE`、`ResourceType.ENERGY`，写错了编译期就报错。
- **没有“原型构造函数”**：官方 `createConstructionSite({x, y}, StructureTower)` 传的是构造函数值；
  Java 没有这种值，用 `StructureType.TOWER` 枚举代替。
- **`/arena` 模块不是每关都有**：`BodyPart` 原型只在部分关卡存在，所以绑定库做成显式登记
  （`GameObjects.registerBodyPart()`）——不登记就不会 import `/arena`，避免其他关卡整份脚本加载失败。

## TeaVM 环境的边界（写代码前心里有数）

- 支持常用的 JDK 子集：`String`、集合、`Stream`、`Math` 等。
  本教学里用到的 `stream().filter()/.count()/.anyMatch()/.toList()`、`Collectors.toList()`、
  `List.of()` 都已用 TeaVM 0.15.0 实测编译通过（产物 `main.mjs` 在 Node + mock 里加载并执行无异常）。
- **不支持**线程、文件 IO；`System.out` 在真机上看不到，日志用 `Game.log`。
- 反射、动态代理这类能力很有限，别用。
- 你的代码每个 tick 都要跑一遍，保持轻量；大计算放到开局或拆到多 tick 完成。

## 产物与关卡的关系

`pom.xml` 里每个关卡一个 TeaVM `<execution>`：一个 `<mainClass>` + 一个 `<targetDirectory>`。
加新关卡就是复制一段 execution，改这两处：

```xml
<execution>
  <id>my-arena</id>
  <goals><goal>compile</goal></goals>
  <configuration>
    <targetDirectory>${arena.output.dir}/my-arena</targetDirectory>
    <mainClass>bot.myarena.Main</mainClass>
  </configuration>
</execution>
```
