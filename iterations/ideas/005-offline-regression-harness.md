# 005 把离线模拟器做成策略回归台

状态：部分已落地（多场景断言与批量入口已进 `tools/tests/`；
mock 胜负判定、脚本化对手、CPU 预算检查仍未排期）

## 背景

v0.1 的 `tools/` 只是个"能跑起来"的模拟器：地形是平的、敌人不会还手、
没有胜负判定，mock 的数值也只是近似。它的定位是验证 API 用法，不是判断策略强弱。

但正因为它是纯 Node、无依赖、几秒钟就能跑完一局，它有潜力变成更有用的东西。

## 想法

把它升级成"策略回归台"：

1. **给 mock 加胜负判定**：按关卡规则实现（基础 CTF 的夺旗、Spawn & Swamp 的 spawn 血量）
2. **加一个脚本化对手**：固定种子的简单 AI，负责制造压力和消耗
3. **跑批**：一个命令跑 N 局不同种子，输出胜率、平均结束 tick、每 tick 的 CPU 占用
4. **CPU 预算检查**：把每一 tick 的实际执行时间打出来，逼近 `cpuTimeLimit` 时报警

## 收益

- 改策略前先看回归数据，而不是"感觉这次打得不错"
- 能在没打开游戏的情况下发现"某个分支每 tick 都在做全地图遍历"这类问题
- 种子可复现，出问题能回放

## 代价

- mock 会越来越像"另一个游戏"，维护成本上升；每次游戏版本更新都可能要跟着改
- 数值一旦和真机偏离太多，回归数据反而会误导决策

## 原则

宁可少，不要假：只实现"策略逻辑会依赖"的规则（能不能走、能不能打、什么时候结束），
不追求复刻伤害公式。凡是猜的数值，在文档和注释里标注是猜的。
