# 05 构建与使用

## 环境要求

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| JDK | 17 或更高 | JDK 17 与 25 都验证过；`pom.xml` 里 `maven.compiler.release=17` |
| Maven | 3.9+ | 需要联网拉插件/依赖（TeaVM、ASM 等） |
| Node.js | 18+ | 只需要在离线模拟器/回归测试时用 |

`mvn` 没绑到 JDK 17+ 时，先设置再构建：

```powershell
$env:JAVA_HOME = "C:\path\to\jdk-17"
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
mvn package
```

用自定的本地仓库时，参数要单独引号传，否则 Maven 会把它当成插件前缀：

```powershell
mvn "-Dmaven.repo.local=D:\maven\repository" package
```

## 方式一：直接用本仓库（自带示例 bot）

```powershell
mvn package
```

产物：

```
dist/spawn-and-swamp/main.mjs     竞技场示例策略
dist/capture-the-flag/main.mjs    抢旗示例策略
dist/harvest/main.mjs             采集循环（最简单的入门示例）
dist/probe/main.mjs               绑定库自检（不是给人玩的）
```

想加自己的关卡产物：复制 `pom.xml` 里任意一段 TeaVM `<execution>`，
改 `id`、`mainClass`（自己的入口类）、`targetDirectory`。
`tools/watch.mjs` 会自动从 `pom.xml` 读到新关卡，不用改它。

### 开发循环（保存即编译）

```powershell
node tools/watch.mjs                 # 盯 src/main/java，所有关卡
node tools/watch.mjs spawn-and-swamp # 只盯一个关卡
```

需要给 mvn 额外参数时用环境变量：`$env:MVN_ARGS='-Dmaven.repo.local=D:\maven\repository'`。

**代码是开局时载入的**：编译完必须重开一局，客户端不会热更新。

## 方式二：在自己的工程里用（推荐给正式开发）

绑定库可以当普通依赖用，你的工程里只留策略代码。步骤：

1. 在本仓库把它装进本地 Maven 仓库（**改过绑定库就要重装一次**）：

   ```powershell
   mvn install
   ```

2. 你自己的 `pom.xml` 加依赖 + TeaVM 插件（照抄本仓库 `pom.xml` 的插件配置）：

   ```xml
   <dependency>
     <groupId>io.github.screepsarena</groupId>
     <artifactId>screeps-arena-java</artifactId>
     <version>0.1.0-SNAPSHOT</version>
   </dependency>
   ```

   TeaVM 的依赖（`teavm-classlib`、`teavm-jso`、`teavm-interop`）在绑定库里是 `provided`（不传递），
   要在自己工程里补上；

3. 入口类写 `@JSExport public static void loop()`，每个关卡一段 `<execution>`；
4. `mvn package`，把游戏客户端的代码目录指向产物目录。

IntelliJ 里直接把这些文件当普通 Maven 工程打开即可，改代码、构建都不用离开 IDE。

## 游戏客户端怎么绑定

```mermaid
flowchart LR
    A["关卡页面：代码设置"] --> B["选择代码目录<br/>（绝对路径）"]
    B --> C["目录根部的 main.mjs<br/>就是这局要跑的策略"]
    C --> D["开局载入<br/>（对局中不变）"]
```

要点：

- 客户端只认**目录根部**的 `main.mjs`，会把该目录下所有文件打包上传（约 10MB 上限，
  固定忽略 `typings/`、`jsconfig.json`）；
- 代码目录按关卡分别保存（教程 10 关共用 `tutorial` 一个目录；每关能不能各自绑定，
  以客户端当前版本为准）；
- **绑定是永久保存的**，之后重玩不用再设。

## 排错速查

| 现象 | 先查什么 |
| --- | --- |
| 日志面板完全空白 | 代码目录是否指对（目录里要有刚生成的 `main.mjs`）；是否重开了对局 |
| 有 `已加载` 但没有 creep 孵化 | 策略层问题：看 `孵化失败：<错误码>`（能量不够/上一只还在孵化是正常的重试） |
| 第一 tick 就抛异常 | 多半是某个原型在当前关卡不存在；线上拿不到 source map，可在产物尾部 `$rt_stringPool([...])` 里搜字符串常量反推 |
| 想确认产物引用的模块对不对 | `node --import ./tools/register.mjs ./tools/sim.mjs` 会做 `/arena` 静态检查 |
| 改了代码游戏里没变化 | ① 构建成功；② 产物时间戳变新；③ 重开对局 |

历史坑（已修复，遇到旧产物仍可对照）：

- `TypeError: $nativeString.charCodeAt is not a function`——把数字 id 当 Java 字符串用；
- `TypeError: Cannot read properties of undefined (reading 'length')`——孵化中的对象没有 id；
- `TypeError: visual.line is not a function`——把 `/game/visual` 的类当模块命名空间用。

细节见 `iterations/ideas/008`、`009`。

## 离线跑

```powershell
# 人工观察：跑 20 tick 的 spawn-and-swamp，打印每 tick 态势
node --import ./tools/register.mjs ./tools/sim.mjs 20 spawn-and-swamp

# 跑任意产物（例如你工程里编出来的那份）
node --import ./tools/register.mjs ./tools/sim.mjs 40 harvest "E:\path\to\dist\harvest\main.mjs"

# 全量回归：4 套 × 字符串/数字 id
node tools/tests/run.mjs "E:\path\to\your-project\dist\tutorial"
```

## 真机验证清单

离线全绿只证明"逻辑和这层 ABI 对了"，不证明安装版引擎的实际行为。第一次上真机：

1. 构建，确认 `dist\<关卡>\main.mjs` 时间戳是刚生成的；
2. 进对应关卡，把代码目录指向该产物目录（绝对路径），**重开一局**；
3. 看日志面板：
   - tick 1 应该有 `[screeps-arena-java] 已加载：…`；
   - 之后每 10 tick 一行 `tick=N 我方 creep=X 敌方 creep=Y`；
   - 没有 `!!` 开头的异常；
4. 想验证 `/game/visual`：把代码目录指向 `dist/spawn-and-swamp`，画面上应出现红色调试线；
5. 想验证绑定库角落：跑 `dist/probe` 一局，日志里的 `probe:` 行应与离线一致
   （孵化中 `id=null`、`adopted=yes` 等）。
