# 06 版本与路线图

## v0.1（已完成）—— 跑通闭环

一句话：**Java 写 → 编译成 `main.mjs` → 真机能加载、离线能回归**。

交付内容：

- 绑定库 `screeps.arena`：`/game` 核心原型 + 全局函数 + `/game/path-finder` + `/game/visual`；
- 三个示例 bot：`bot.spawnswamp`（竞技场）、`bot.ctf`（抢旗骨架）、`bot.harvest`（采集循环）；
- 自检 bot `bot.probe`：把"关卡用不到、出问题却很难查"的角落跑一遍（19 项断言）；
- 一关一产物：`dist/<关卡>/main.mjs`，客户端指到哪个目录就是在跑哪一关；
- 绑定库可以 `mvn install` 成 jar 被外部 IntelliJ 工程依赖（真实消费者已在用）；
- 离线模拟器 + 回归套件：4 套 × 字符串/数字 id 两种模式；
- 文档：本套 `docs/` + `教学/`（游戏教程中文 + Java 对照）+ `iterations/`（想法池与版本记录）。

## 已知差距 / 下一步

按优先级：

1. **真机复验（最重要）**：修复后的产物已重建、离线 8 组全过，但还没有在真机上重开
   教程第 7 关实跑；竞技场实战（Spawn & Swamp / CTF）需要完整版游戏。
   清单见 [05 构建与使用](05-构建与使用.md) 的"真机验证清单"。
2. **CTF 策略重写**：现在的抢旗/回旗判定只是骨架，要按游戏实际规则重写（属于策略层）。
3. **教程 2~10 关的 Java 版本**：已有一套逐关可通关代码（在外部工程里，见 `教学/`）。
4. **赛季关卡**：Collect & Control 的 `ScoreCollector`、`AreaEffect` 等关卡原型还没有。
5. **体积与 CPU 优化**：产物 110~130KB 级别；先把量化做好，再谈 `ADVANCED` 优化或裁剪。
6. **多模块拆分**：绑定库/示例/工具拆开，方便只引库。

## 版本约定

- 绑定库版本号在 `pom.xml`（当前 `0.1.0-SNAPSHOT`）；
- 每完成一个阶段性目标，在 `iterations/` 下建一个版本文件夹记录"交付了什么、怎么验证的"，
  想法池里的条目被排期时挪进版本说明；
- 发布到 GitHub 时按 `v0.1.0` 这类 tag 打版本。
